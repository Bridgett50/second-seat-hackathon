# Brief rules + claims check: seeded-mutant table

Generated by `node eval/rules/run.mjs --write` (seed 102, up to 2 targets per source and operator). $0: no model calls. Sources (read-only): the recorded Spark briefs for hero and dev01-03 with their transcripts; claims verdicts from `eval/results/support-judgments-frozen-live.jsonl`. Inputs and the generated set are pinned in `eval/rules/SHA256SUMS`.

A mutant is **caught** if `verifyBrief` blocks it, or if the mutated entry gains an escalation it did not carry in the unmutated control. Baseline = flags-only (`validateBrief` alone, the pre-verification behaviour): it can add flags but never refuses.

## Claims check: fail-closed vs fail-open

Every recorded support verdict is fed in well-formed, under each corruption, and missing. **Fail-closed** = `verifyClaims` (`@second-seat/core`). **Fail-open** = a reference model of the behaviour documented at Meta legal-agent-workshop `agent/verification/verify_claims.py` L50-54 (commit 2a8efc8): an unreadable judgement does not block. It still blocks when it can read a `partial`/`unsupported` grade.
