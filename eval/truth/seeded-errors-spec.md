# Seeded-error mutation spec (DRAFT, not sealed)
Source: supported entries in hero.labels.json and dev/*.labels.json (expected_support = "supported"). Each mutant copies one entry, changes ONE thing, keeps the citations unchanged. Expected judge grade for every mutant: partial or unsupported (or missing_qualifier set for M3). Suite FAILS if the support judge is disabled (mutants would pass the lexical/ID checks).

| Type | Rule | Example (source -> mutant) | Expected |
|---|---|---|---|
| M1 wrong date | Replace due date/date with a plausible different date (±1–14 days, or swap 15th/30th) | H-A1 "artwork by Oct 30" -> "by Nov 6" | unsupported |
| M2 wrong owner | Swap assignee to another attendee | D4-A2 Sam prints -> Hana prints | unsupported |
| M3 dropped qualifier | Delete the required qualifier | H-Q1 "41c plus tax and freight" -> "41c per unit"; D2-D1 drop "if QA passes"; D2-Q1 drop "projected" | partial + missing_qualifier |
| M4 invented decision | Turn an open question/request into an agreed decision | H-U1 -> "Brightline committed to a backup delivery"; D5-U1 -> "agreed to Nov 6" | unsupported |
| M5 hedge->certainty (paraphrase drift) | "will try / probably / about" -> "guaranteed / will / exactly" | H-A3 "we'll try early next week" -> "guaranteed by Monday" | partial/unsupported |

Target set: every eligible supported entry x every applicable mutation type (generated by a deterministic script with a fixed seed; generator + output hashed with the truth files). Draft estimate: ~40–60 mutants from hero + dev. Controls: the unmutated originals (expected supported) measure false alarms. Report catch rate and false-alarm rate with n and Wilson 95% CI. No numbers until a real run.
