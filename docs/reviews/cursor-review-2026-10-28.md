## Summary

The #100 factories forward `maxAttempts` and `fetchImpl`, and their HTTP error strings no longer include response bodies. The implicit default is still 4 attempts with no upper bound, and a non-JSON body can still leak through `JSON.parse`. The live web path is `MuseClient`, which still copies 500 characters of the provider body into the error the browser renders. Modal `serve` is an unauthenticated public vLLM endpoint. `/briefs/demo`, the static build, and the Demo Mode switch cannot start a model call. Residual-PII checks are exact-match, so case, homoglyph, spacing, and separator-free phone variants pass both `verifyRedaction` and the live send gate. The verification layer blocks malformed briefs and unreadable verdicts, is not wired into the session, and has the fail-open holes below. Known issues 1–3 still match the code and the published rules table.

## Dead code

## Wiring the verification layer

Wiring is safe only as a gate in front of display, not as a replacement for approval. `verifyRedaction` always sets `ownerReviewRequired: true`; a pass must not auto-approve or auto-send. Call it with the approved preview and `findResidualPII` after F3, not with a fresh `MockRedactor` pass. `verifyBrief` is pure and offline; show the brief only when `passed` is true, and show escalations rather than treating them as clean. Do not call `SparkSupportJudge` from the web request. `verifyClaims` should read a verdict you already have. The default judge makes live calls and retries. Demo and offline sessions should keep using the fixture path.
